## 二、 精选项目事实（Projects Facts）

### 2.1 联想设备管理平台｜企业终端运维 Agent 智能工作流
- **项目性质**：成熟商业 B 端 SaaS 平台，核心 AI 产品经理与体验架构师。
- **业务背景**：纳管 260+ 家企业、超过 100 万台活跃终端。管理员跨 3 个模块处理运维工单平均需 7 步操作，面临信息分散、批量高危操作风险巨大的痛点。
- **三方责任模型**：
  - **AI 意图编排面**：负责多轮对话、槽位抽取（Slot Filling）与意图分类。大模型仅有“意图建议权”，绝无底层 API“物理调用权”；
  - **平台确定性鉴权面**：后端网关强制校验 RBAC 权限与前置状态探针；
  - **HITL（Human-in-the-Loop）确认面**：高危操作强制由持权人员在平台界面二次点击弹窗，生成一次性防重放 Token 验签放行。
- **风险分级路由**：
  - **L1（只读查询）**：如查询设备内存、电池健康度，模型解析槽位后直接走 API 查询；
  - **L2/L3（高危写操作）**：如远程重启、批量静默软件部署、格式化，大模型代码级阻断直接执行，强制走完五步安全闭环（探针预检 → RBAC 鉴权 → 影响面明确告知 → 人工二次验签 → 审计日志）。
- **异常探测与自愈**：
  - 设备同名歧义识别：主动反问返回带 IP/MAC 的候选卡片；
  - 离线状态预检探针：设备离线超过阈值直接阻断并转入排查工单；
  - 超时与自愈：接口超时（>5s）自动重试 1 次，失败优雅回退人工工单。
- **量化收益**：覆盖 260+ 企业、100 万+ 终端，关键高频路径缩短 70%，高危未授权误操作 100% 确定性拦截。
- **防守要点（面试追问）**：如果用户输入提示词注入诱导大模型执行删除，系统如何防御？——执行放行权在物理层完全剥离出大模型，没有人工前端点击生成的防重放签名 Token，后端安全网关直接 403 阻断，模型出现任何幻觉都无法越权。

### 2.2 STAR 企业智能知识资产治理与问答平台（LLM + RAG）
- **项目性质**：企业级 RAG 知识管理与智能问答系统。
- **核心痛点**：企业文档多版本并存（如 2023 与 2025 年差旅标准），纯依靠向量相似度极易召回已废弃的旧制度，导致严重的“上下文腐化（Context Rot）”与答案胡说八道。
- **治理与切片方案**：
  - **业务语义切片**：摒弃固定字数暴力切片，基于 Markdown H2/H3 标题切片，保留父子层级上下文与表格原子化；
  - **时效元数据强前置过滤**：文档入库强制打标 `effective_date`、`expire_date` 和 `version_status`。检索前注入强过滤规则，物理阻断废弃切片进入上下文窗口。
- **三层护栏防线**：
  - 强制依据展示（Grounding）：回答末尾必须标注依据段落出处，支持跳转锚定；
  - 置信度低反问追问；
  - 置信度不足代码级明确拒答，杜绝主观捏造。
- **评测与自愈飞轮**：
  - 搭建 200+ Golden Dataset 黄金测试集（真实高频问答 + 30 条越权诱导 + 20 条新旧版本冲突）；
  - 确立三大客观指标：检索召回率 Recall@3 (>88%)、生成忠实度 Faithfulness (>92%)、拒答准确率 (>98%)；
  - 员工端前端点踩反馈自动流转至管理端治理看板，形成“点踩收集 → 规则打标 → 自动化回归评测”的闭环。

### 4.1 为什么从 UI/UX 和传统 B 端转向 AI 产品经理？
- 传统 B 端沉淀了 7 年严谨的系统边界、复杂权限、状态机流转与可用性工程底座；
- 生成式 AI 落地企业业务存在巨大断层：算法团队擅长搞出概率输出的模型，但企业客户需要的是确定性、带权限、不出事的可用系统；
- 兼懂严谨系统逻辑、用户体验与 AI 工程的人，才能构建真正可用、可控的工业级 Agent。

### 4.2 为什么强调“评测即 PRD”？
- 传统 PRD 描述确定性按钮与弹窗，但无法约束概率大模型的生成边界；
- “评测即 PRD”将需求转化为百条级成对测试集（Question, Context, Ground Truth, Assertions）；以检索召回率、忠实度与拒答率作为唯一客观研发门禁。
